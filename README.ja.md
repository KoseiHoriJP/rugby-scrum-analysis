# ラグビースクラムのフェーズ分類パイロット

[English](README.md) | [日本語](README.ja.md)

提供された **Rugby Scrum Pilot Dataset** を、スクラムのフェーズを人手で
ラベル付けできる形に整備するためのリポジトリです。初回のビルドでは、
3試合・5本のクリップから抽出した279フレーム、1,378件の人物の自動検出結果、
COCO形式の23,426点のキーポイントを保持します。フェーズのラベルを自動で
作り出したり、YOLOの推定結果を人手で確認済みの正解姿勢として扱ったりはしません。

## 第19条全体に対応したアノテーション設計

新しいデータセット向けに、[アノテーション仕様全体](data/source_catalog/scrum_full_annotation_plan.md)、
[条項ごとの対応表](data/source_catalog/law19_rule_coverage.md)、
[空のアノテーション表](data/source_catalog/annotation_templates_full/)を用意しています。
通常のプレーを含め、提供された第19条の内容全体を対象とします。
これらは仕様書とテンプレートです。既存のブラウザーツールへの項目追加や、
参照先の画像・動画の内容確認はまだ行っていません。

## 新しいスクラム映像の収集・切り出しを自動化する

追加映像の収集には、[Mac向けの自動切り出し手順](docs/AUTOMATIC_CLIPPING.md)を
利用できます。レフェリーのCrouch／Bind／Setの発声候補を検出し、ブラウザーで
各スクラムの実際の終了位置とカメラ視点を確認した後、`aerial/` と `side/` に
クリップを一括出力します。各クリップはCrouchの15秒前から、確認済みの終了位置まで
を含みます。Setの10秒後などの固定時刻では打ち切りません。任意で利用できる
カメラ視点モデルの提案も、確認されるまでは未検証のまま扱います。

## ダウンロード

- [データセットとオフラインのラベル付けツール（5.2 MB）](https://github.com/KoseiHoriJP/rugby-scrum-analysis/raw/refs/heads/main/artifacts/Rugby_Scrum_Phase_Pilot_v1.zip)
- [データ整備用コードと元のパイロットのメタデータ・プレビュー（5.1 MB）](https://github.com/KoseiHoriJP/rugby-scrum-analysis/raw/refs/heads/main/artifacts/Rugby_Scrum_Dataset_Tools_v1.zip)
- [SHA-256チェックサム](artifacts/SHA256SUMS)

データセットのZIPを展開し、その中の `review.html` をSafariまたはChromeで開くと、
サンプルフレームにラベルを付けられます。`review.html` と同梱の `previews/` フォルダーは
同じ場所に置いてください。ページを閉じたり再読み込みしたりする前に、下書きをJSONで
保存します。作成済みのラベル付けツールを使うだけなら、インストールは不要です。
初期状態のラベルはすべて空欄です。

ツール用ZIPには、ビルダー、テスト、ドキュメント、取り込み済みの元のメタデータ・
プレビューを収めた `rugby-scrum-analysis/` フォルダーが入っています。
再ビルドする場合は、そのフォルダーで `python scrum_dataset.py` を実行してください
（Python 3.10以降とFFprobeを推奨）。

## ビルド

Python 3.10以降があれば利用でき、追加のPython依存パッケージのインストールは不要です。
FFmpegに含まれるFFprobeで、プレビューのフレーム数と5 fpsの時刻対応を確認します。
FFprobeがなくてもメタデータは出力できますが、フレーム位置を対応付けた動画の
ラベル付け機能は無効になります。

以下のコマンドは、このチェックアウトのルートで実行してください。
すでに用意された分離環境のチェックアウトを利用でき、Git worktreeの作成は不要です。

```sh
# 新しくアップロードしたアーカイブを取り込み、検証してビルドする。
python scrum_dataset.py --archive /path/to/Archive.zip

# または、取り込み済みのファイルから新しい出力バージョンを作る。
python scrum_dataset.py --input data/raw/pilot --output data/processed/pilot-v2

python -m unittest discover -s tests -v
```

取り込み処理はmacOSの付加メタデータを無視し、安全でないパスや既存ファイルの
上書きを拒否します。元データの作業ディレクトリと生成物はGitの管理対象外です。
配布用にまとめた2つのZIPと、そのチェックサムはGitで管理します。元のCSVと
座標値は変更せず、入力ファイルのハッシュとモデルの由来を記録します。

## スクラムのフェーズをラベル付けする

`data/processed/pilot-v1/review.html` をブラウザーで開きます。
プレビュー動画は隣の `previews/` フォルダーに入っているため、まとめて保持してください。
アップロード、ログイン、サーバー、外部ライブラリは不要です。ダウンロードしたZIPを
使う場合は、先に展開してください。

[アノテーションガイド](docs/ANNOTATION_GUIDE.md)に沿ってレビュアー名を入力し、
プレビューの前後の流れを確認しながらサンプルフレームにラベルを付けます。
別途レビューを受けるまでは、ラベルは**下書き**として扱います。ページを閉じる前に、
再開用のJSONと分析用のCSVを両方出力してください。下書きはタブのメモリー内にのみ
保持され、ページを再読み込みすると失われます。再開時は、出力済みのJSONを読み込みます。

対象となる4つのフェーズは、`formation`（形成・準備）、`engagement`（接触・組み合い開始）、
`drive`（組み合い後の攻防）、`release`（スクラムの解消・離脱）です。
必要に応じて `not_scrum`（スクラム以外）または `uncertain`（判断困難）を使います。
空欄は未ラベルの状態です。YOLOの検出信頼度からフェーズを決めてはいけません。
フレーム単位のフェーズラベルは、検出された個々の人物ではなく、スクラム全体に付けます。

## 出力ファイル

| ファイル | 内容 |
| --- | --- |
| `frames.csv` | 全サンプルフレーム、時刻の対応、映像ファイルの有無、データ分割 |
| `splits/*.csv` | 同じ試合が複数の区分にまたがらない、学習・検証・テスト用のフレーム一覧 |
| `poses.jsonl` | 1フレームにつき1レコード。人物検出が0件のフレームも含み、各検出には17点の関節を保持 |
| `frame_annotations.csv` | レビュー用の欄を備えた、279フレーム分の空の手動フェーズラベル |
| `phase_schema.json` | ラベルの一覧、フレームを識別する固定キー、レビュー状態の定義 |
| `person_annotations.csv` | 任意の人物・姿勢レビュー用。未確認の追跡IDは作成しない |
| `review.html`, `previews/` | オフラインの下書きラベル付けツールと、骨格を重ねた5本の動画 |
| `validation_report.json` | 件数、信頼度の統計、警告、各データ区分の規模 |
| `provenance.json`, `clips.csv` | 入力チェックサム、処理のメタデータ、元映像の出典・権利表記 |

`confidence_mask` は、モデルの信頼度が設定したしきい値以上であることを表します
（既定値は0.5）。関節が実際に見えているか、推定が正しいか、人手で確認されたかを
示すラベルではありません。`poses.jsonl` の座標は、元動画全体を基準としたピクセル値の
まま保持します。切り出し領域の座標へ変換するには、ROIの左上のオフセットを引きます。
プレビューの右端・下端にはエンコーダーによる余白が付く場合があります。
プレビューを拡大・縮小して元画像の代わりにしてはいけません。
`detection_index` は各フレーム内だけの識別番号で、`track_id` はnullのままです。

## パイロットのデータ分割と制約

| 区分 | 試合グループ | クリップ数 | フレーム数 |
| --- | --- | ---: | ---: |
| 学習 | ウルグアイ対アルゼンチンXV、2018年 | 2 | 105 |
| 検証 | ミラノ対カルヴィザーノ、2010年 | 1 | 48 |
| テスト | イタリア対チリ、2025年 | 2 | 126 |

分割は `configs/pilot_splits.json` で明示した、試合単位の暫定的なホールドアウトです。
80／10／10の比率を実現したものではありません。対象は3試合のみで、視点や解像度にも
大きな差があります。テスト用の試合を見ながらモデルや設定を調整しないでください。
これはラベル付けと研究のための初期検証用データであり、未知の試合にも通用することを
信頼性高く主張できる規模ではありません。

アップロードされたアーカイブには骨格を重ねたプレビューが含まれますが、
**元動画は含まれていません**。プレビューはフェーズの確認に利用できますが、
骨格表示のない姿勢学習用画像の代わりにはなりません。元のMP4を入手できた場合は、
`data/raw/pilot/clips.csv` に記載されたパスへ配置してください。骨格表示のない画像の
抽出や姿勢推論の再実行には、元動画が必要です。このビルダーは姿勢推論やモデル学習を
行いません。現時点で、**人手でラベル付けされたフレームは0件**です。

対象範囲と出典・権利表記は、[データセットカード](docs/DATASET_CARD.md)を参照してください。
空撮映像の候補リンク10件は、動画をダウンロードしておらず、学習データにも含めていません。
